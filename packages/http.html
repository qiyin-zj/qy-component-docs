@qynpm/http ​

起印公共 HTTP 客户端。它用 Qy 自有类型统一请求、响应模式和错误分类，当前内部使用 Axios，但不会向消费者公开 Axios 配置、响应或错误类型。

适合浏览器应用中需要统一 Bearer token、业务 envelope、文件响应和认证失效回调的接口调用。不负责刷新 token、重试、缓存、下载保存、提示 UI、登出、路由跳转或多个 401 的去重。

安装与本地联调 ​

源码中的版本号不等于该版本已经发布。先从 npm registry 或消费者 lockfile 确认目标版本确实可用，再安装：

bash
pnpm add @qynpm/http

包只公开根入口 @qynpm/http，同时提供 ESM、CommonJS 和类型声明。本地联调时，由消费者显式 alias 到本仓库源码入口或已存在的构建产物；这类 alias 不是 npm 发布契约，也不要为了阅读文档重建正在被其他项目使用的 dist。

快速开始 ​

ts
import { createQyHttpClient } from '@qynpm/http'

let currentSessionId = 'login-1'

const http = createQyHttpClient({
  baseURL: '/api',
  getToken: () => sessionStorage.getItem('access-token'),
  getSessionIdentity: () => currentSessionId,
  async onUnauthorized({ sessionIdentity, error }) {
    // 请求发出后用户可能已经重新登录。只处理仍属于当前会话的 401。
    if (sessionIdentity !== currentSessionId) return
    console.warn(error.message)
  },
  onError(error) {
    console.error(error.kind, error.message)
  }
})

const result = await http.request<{ id: number; name: string }>({
  url: '/items/1',
  mode: 'data'
})

// data 模式在响应没有自有 data 字段时会返回整个 envelope，先按契约收窄。
if (result && 'id' in result) console.log(result.name)

创建客户端 ​

ts
const http = createQyHttpClient({
  baseURL: '/api',
  timeout: 300_000,
  withCredentials: true,
  successCodes: [200],
  unauthorizedCodes: [401]
})

CreateQyHttpClientOptions<Session>：

字段类型默认值说明
baseURLstring必填请求基础地址。
timeoutnumber300000Axios 请求超时毫秒数。
withCredentialsbooleantrue是否携带跨域凭据。
getToken() => string | null | undefined-每次发送前读取 token；有值时写入 Authorization: Bearer <token>。
getSessionIdentity() => Session-每次发送前捕获会话标识，原样交给未授权回调。
successCodesreadonly (string | number)[][200]envelope 业务成功码。
unauthorizedCodesreadonly (string | number)[][401]envelope 业务未授权码。
onUnauthorized(context) => void | Promise<void>-unauthorized 错误回调。客户端会等待它完成。
onError(error) => void | Promise<void>-除 unauthorized、canceled 外的错误回调。客户端会等待它完成。

successCodes 和 unauthorizedCodes 使用严格类型匹配：数字 401 不等于字符串 '401'。HTTP 状态 401 始终分类为 unauthorized；其他非 2xx 状态分类为 http。

回调抛出的异常会被忽略，最终仍拒绝原来的 QyHttpError，不会被回调错误替换。取消请求不调用 onError 或 onUnauthorized。

请求参数与编码 ​

client.request(request) 接受 QyHttpRequest：

字段类型默认值说明
urlstring必填相对或绝对请求地址。
methodGET | POST | PUT | PATCH | DELETEGETHTTP 方法。
params标量记录-使用 URLSearchParams 追加查询参数；null、undefined 跳过，false、0、空字符串保留。
dataunknown-请求体。
headersReadonly<Record<string, string>>-请求头；token 会写入 Authorization。
signalAbortSignal-用 AbortController 取消请求。
modefull | data | array | binaryfull返回值模式。
bodyEncodingjson | json-utf8 | formjson非 FormData 请求体的编码方式。

编码规则：

  • json：JSON.stringify(data)，并设置 application/json。
  • json-utf8：同样序列化 JSON，并设置 application/json;charset=utf-8。
  • form：只接受非空对象，递归编码为 bracket key；空字符串、null、undefined 被跳过。
  • FormData：直接交给浏览器和 Axios 生成 multipart boundary，不手动设置 Content-Type。
ts
await http.request({
  url: '/search',
  params: { page: 2, active: false, keyword: '' }
})

await http.request({
  url: '/items',
  method: 'POST',
  data: { name: '样品' },
  bodyEncoding: 'json-utf8'
})

await http.request({
  url: '/filters',
  method: 'POST',
  data: { nested: { id: 1 }, tags: ['a', 'b'] },
  bodyEncoding: 'form'
})

const controller = new AbortController()
const pending = http.request({ url: '/slow', signal: controller.signal })
controller.abort()
await pending.catch(() => undefined)

四种响应模式 ​

模式返回值约束
fullQyHttpEnvelope<T>默认模式；JSON 顶层必须是非数组对象。
dataT | null | undefined | QyHttpEnvelope<T>仅当 envelope 拥有自己的 data 字段时返回其值；字段缺失时返回整个 envelope，不能假定总是 T。
arrayT[]JSON 顶层必须是数组，不读取 envelope。
binaryQyBinaryResponse返回 Blob、HTTP 状态和小写响应头记录。不会自动保存文件。
ts
const envelope = await http.request<{ id: number }>({ url: '/items/1' })
const data = await http.request<{ id: number }>({ url: '/items/1', mode: 'data' })
const rows = await http.request<{ id: number }>({ url: '/items', mode: 'array' })
const file = await http.request({ url: '/export', mode: 'binary' })

console.log(envelope.code, data, rows.length, file.status, file.body, file.headers)

普通模式要求响应 Content-Type 包含 json，否则是 protocol 错误。binary 会识别 JSON content type，以及内容看起来像对象或数组的伪装二进制响应：先按业务码分类失败；成功 JSON 也不会被当成文件返回，而是 protocol 错误。

错误模型 ​

所有请求失败都以 QyHttpError 拒绝。公开字段为 kind、message、可选 status、可选 code 和可选 cause。

kind含义
unauthorizedHTTP 401，或 envelope code 命中 unauthorizedCodes。
http其他非 2xx HTTP 状态。
business2xx envelope 带 code，但未命中成功码或未授权码。
network网络或 transport 失败。
timeout请求超时。
canceledAbortSignal 或 transport 取消。
protocolJSON、数组、binary 或 form 不符合当前模式约定。
ts
import { QyHttpError } from '@qynpm/http'

try {
  await http.request({ url: '/items' })
} catch (error) {
  if (error instanceof QyHttpError) {
    console.log(error.kind, error.status, error.code)
  }
}

全部公开导出 ​

运行时仅导出 createQyHttpClient 和 QyHttpError。根入口还导出以下类型：

  • CreateQyHttpClientOptions<Session>
  • QyBinaryResponse
  • QyHttpClient
  • QyHttpEnvelope<T>
  • QyHttpErrorKind
  • QyHttpMethod
  • QyHttpRequest
  • QyResponseMode
  • QyUnauthorizedContext<Session>

宿主边界与迁移 ​

  • 旧项目可在宿主 adapter 内把原请求配置转换成 QyHttpRequest，不要把 Axios 类型继续扩散到新公共接口。
  • 宿主负责提示、登录弹窗、token 刷新、登出、导航和并发未授权去重。
  • sessionIdentity 是请求发送时的快照。处理未授权前必须与当前会话比较；旧请求返回的 401 不能清除用户后来建立的新登录状态。
  • 本包不承诺自动重试、请求缓存、进度上报、文件名解析或下载保存；需要时由宿主在公开返回值之上实现。
