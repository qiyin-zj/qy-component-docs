qy-workspace：旧 ERP 证据与迁移来源 ​

角色 ​

qy-workspace 是旧 ERP 行为、调用频率和迁移差异的来源，不是 qy-components 的新架构、公共 interface、发布入口或版本权威。其根 AGENTS.md 明确该仓库包含业务子项目和私有 @qiyin/* 库，且许多引用必须按 Vite alias 与真实 import 解析。

查证与验收入口 ​

  • 工作区结构、ERP 命令与 alias 解释规则：消费者仓库的 AGENTS.md。
  • 每个待迁移调用的真实解析：该项目及目标子项目的 vite.config.ts、tsconfig、源码 import 与调用链；不要从包名推断落点。
  • ERP 侧验证：按目标子项目现有命令执行；根规则列出的 ERP 入口为 pnpm run dev --root=erp、pnpm run build --root=erp 和项目测试。迁移验收仍须选择实际受影响页面。

可以作为来源的内容 ​

旧组件的可观察行为、真实调用频率、字段/视觉兼容要求和未迁移缺口，可用来形成 Candidate 或校验新的 Qy interface。提取前先对照 迁移流程 和目标消费者，避免只从旧页面猜测公共边界。

跨系统组件迁移盘点（2026-08-07） ​

本轮盘点同时覆盖 packages/qiyin/components 和各业务系统自己的 packages/*/src/components，排除 node_modules、dist、coverage 与 webpack 构建产物。候选优先级综合考虑跨系统重复、当前真实引用、已有 Qy 能力和业务耦合程度；目录中存在同名文件不等于已经证明应进入公共包。

重复证据包括：SvgIcon 在 11 个系统中存在相同实现，IconSelect 在 9 个系统中存在相同实现，Screenfull 在 8 个系统中存在相同实现；FileUpload 分布于 10 个系统；Breadcrumb、SizeSelect、DictTag、RightToolbar、TreeSelect、ImagePreview、ImageUpload 等旧后台组件在约 5 至 6 个系统重复。业务侧还存在 SelectStaff、Category、Log，以及 foundation、market、quotation、uni-app-market-quote 之间重复的 SelectAttribute、FormCraft、FormProduct。quotation 与 uni-app-market-quote 的成套报价组件属于业务模块复制，不按基础 UI 单组件处理。

基于这些来源形成的当前处理结果如下，不代表迁移或修改 qy-workspace 消费代码：

  1. QyIcon、QyIconPicker 和 QyFullscreen 已由 @qynpm/ui 发布；消费者采用仍是独立任务。
  2. QyDictTag、QyRichTextEditor、QyRichTextViewer、QyExcelPreview 以及角色人员、属性、材质属性、工艺、基础产品和工序选择器已发布，尚未迁移消费者。
  3. 文件上传先比较旧 FileUpload 与现有 QyUpload、QyFilePicker、QyImageUpload 的差异，优先补兼容或迁移 adapter，不新建重叠上传实现。
  4. 业务选择器批次已经随 @qynpm/pickers@0.0.4 发布；工序属性等复合能力继续独立评估。业务 API、路由和新增表单仍由宿主或业务 adapter 注入。
  5. 富文本编辑/只读展示、电子表格预览与导入按各自依赖和业务策略规划独立能力包，不塞入基础 UI 根包。

完整的已发布能力、功能缺口、候选顺序和多 renderer 未实现入口见 公共组件现状与后续路线。

高杠杆能力复核（2026-08-22） ​

本轮按 Vue/TS/TSX 源码文件复核真实调用面，并排除 dist、node_modules、coverage 和公开构建产物。数量用于判断相对收益，不代表这些调用已经迁移或接口完全同构：

  1. 旧 useCol() 约覆盖 375 个源码文件，是当前整体收益最高的能力簇。下一步应在 @qynpm/table-schema / @qynpm/table 建 ERP runtime adapter，承接权限、确认反馈、列缓存和资料详情等宿主 seam，不新增平行表格组件。
  2. 旧本地 QyDialog 类入口覆盖 330 多个源码文件，useCreateInstance() 约覆盖 207 个文件；338 个真实标签文件的高频协议包括宽度、标题、modelValue/v-model、确认/取消、layout、confirmProps、全屏和生命周期事件。ERP 另有 6 个源码文件真实使用地址弹窗包。当前已完成并发布 QyDialog 与旧协议桥接 L3 PRP（内部记录：docs/prps/qy-dialog-v2-legacy-bridge-v1/overview.md）：QyDialog 当前契约不兼容旧接口，独立 @qynpm/qy-dialog-legacy 集中映射真实旧协议，QyAddressDialog 只保持地址协议；动态实例继续复用 useCreateInstance。本记录不授权修改 qy-workspace 页面或 alias，也不表示 qy-workspace 已采用新版本。
  3. FileUpload 仍分布于 10 个系统，约 69 个源码文件直接使用 el-upload，且普通上传、WebDAV 与大文件分片并非同一协议。先形成 QyUpload、QyFilePicker、QyImageUpload 与旧实现的差异矩阵，再以 transport 或宿主 adapter 补现有上传族，不增加第四套重叠组件。
  4. 旧 Pagination 约覆盖 270 个源码文件。现有 QyPagination 已具备核心分页能力，优先在 qy-workspace 建私有 adapter 映射旧 page / limit / pagination、页大小选项和 auto-scroll；没有真实公共缺口前不扩张发布接口。

上述四项的消费者迁移均保持 Candidate；本次复核只记录路线，不授权修改 qy-workspace、创建 PRP 或迁移消费者。

已由现有公共能力覆盖的旧入口不再据此重复规划新组件：SvgIcon 对应 QyIcon，旧树选择、图片预览、图片上传、分页、表格、查询表单、弹窗和商品/店铺/普通人员选择分别核对现有 @qynpm/ui、@qynpm/admin-patterns、@qynpm/table、@qynpm/form 与 @qynpm/pickers。是否迁移任何消费者必须由对应项目另行立项，本清单不授权修改 qy-workspace。

旧 Breadcrumb、HeaderSearch、Hamburger、TopNav、TagsView 等后台框架壳整体映射到 admin-shell / admin-framework，不作为普通基础组件逐个重做。拼版 Canvas、三维包装预览、订单关联、业务日志和成套报价编辑器留在未来 qy-workspace 领域包或业务 adapter，不进入通用 UI 包。

不得带入公共包的规则 ​

不得复制其目录结构、Vite alias、私有 @qiyin/* 源码引用、ERP 路由/状态、接口、payload 或临时补丁。旧行为证据不自动证明能力应被发布或已被新消费者采用。
