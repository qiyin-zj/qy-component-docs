公共组件现状与后续路线 ​

状态：当前权威（能力盘点与后续任务入口）。本文件回答“已经有什么、还缺什么、下一项是什么、哪些只是旧项目来源、哪些多 renderer 入口尚未实现”。具体公开 interface、版本和可导入入口仍以各包 package.json、exports、声明、源码、测试与发布产物为准。

使用规则 ​

  • 本文件不复制每个组件的完整 props、events、slots 或 expose；使用方式以目标包 README 和声明为准。
  • Published、Adopted 等状态含义以 公共能力生命周期 为准。已发布不表示 qy-permission、qy-origin-app 或 qy-workspace 已采用。
  • “功能缺口”包括已确认的兼容债务和有来源证据的扩展点，不等于当前组件不可用，也不自动授权实施。
  • “未写 PRP”表示仍须先确认功能点、归属包、公共 interface 和验收入口；不能直接开始编码。

多 renderer 与多入口：当前未实现项 ​

当前只有 Vue 3 + Element Plus implementation。下表中的入口和实现均尚未存在；这是明确暂缓的架构工作，不是当前发布缺陷。

模块当前真实入口尚未实现未来触发后优先方向
@qynpm/form只有包根入口@qynpm/form/element、@qynpm/form/naive、Naive adapter先冻结共享 schema/core，再由同包可选子路径承载 renderer；根入口保留兼容策略，不能维护两套业务逻辑
@qynpm/ui根入口和按组件子路径，内部以 Element Plus 为主Naive UI 第二 implementation、运行时 framework prop/provider、全局 renderer 注册器简单组件优先保持业务导入不变并替换内部 implementation；复杂组件按模块增加真实 adapter，不建立全量平行入口
@qynpm/table-schema当前包根入口；已有内部 core/Element 目录证据对外 Element/Naive renderer 子路径、第二表格 renderer保留 schema core；目标表格框架确定后单独设计 renderer 包或子路径

启动第二 renderer 的必要条件 ​

只有同时满足以下条件，才能把上表项目从“暂缓”升级为 Planned：

  1. 已确定目标框架和首个真实消费者。
  2. 已列出当前 Qy interface 与目标框架的行为差异，而不是只比较组件名称。
  3. 已决定 peer dependency、构建产物、exports、样式 tokens 和宿主 runtime。
  4. 已有同一行为矩阵可同时验收当前 implementation 与第二 adapter。
  5. 已证明新增入口比消费者自行适配更有长期收益。

在这些条件满足前，新组件仍需预留可替换 implementation 的 seam，但不创建空的 /naive、/element、provider 或注册器。

后续文档工作顺序 ​

  1. QyDictTag、@qynpm/rich-text、@qynpm/excel-preview 与领域选择器批次已经发布；后续由具体消费者独立采用和验收。
  2. 建立上传族差异矩阵，决定补现有模块还是增加业务 adapter。
  3. 按 ERP 真实页面建立 table runtime adapter 迁移卡，不把宿主权限和接口写进公共包。
  4. 富文本、表格文件预览/导入、领域选择器分别形成候选说明；前两项已有在制 PRP，后续仍须以长期文档承接边界。
  5. 第二 renderer 只有满足触发条件后才新增 ADR 和分阶段 PRP；当前不提前创建实现任务。
