本页目录

UI 公共 interface ​

状态：当前权威（新增与变更公共契约的治理口径）。当前可发布的组件及子路径仍以 packages/ui/package.json 的 exports、对应 .d.ts 和发布产物为准。

Qy 所有权 ​

业务侧依赖的是 Qy 定义的组件名称、props、emits、slots、expose、默认行为和 tokens。每项新增或变更都必须在 Qy 语义下命名、文档化并以组件测试/声明验证；不能把底层库名称、默认行为或实现对象直接提升为业务契约。

契约面Qy 负责的内容不应新增为公共依赖的内容
props / defaults输入语义、默认值与兼容策略Element Plus prop 类型、隐式底层默认值
emits事件名、触发时机和 payload厂商私有事件或回调对象
slotsQy 命名、上下文与兼容承诺底层组件的未封装 slot 细节
exposeQy 明确承诺的方法和返回语义组件实例、私有 DOM、VNode/Node/Store
tokensQy tokens 及其视觉语义业务必须直接使用的 --el-* 变量

当前实现与历史债务 ​

UI 当前维护 Vue 3 + Element Plus implementation，不是已经多框架兼容的 renderer 层。Element Plus 依赖和内部 import 可以存在；新增公共 API 不得扩大厂商类型、实例、私有 DOM/VNode/Node/Store、私有事件或 --el-* 漏泄。

现有 packages/ui/qy-input/index.d.ts 的 QyInputProps / QyInputType / autosize，以及 packages/ui/qy-input-number/index.d.ts 的 QyInputNumberProps，仍引用或继承 Element Plus 类型。这是已登记的兼容债务：后续按模块审查、迁移和验证；本文件不宣称其已经框架中立，也不要求本阶段批量修复。

变更检查 ​

  1. 先核对根入口或子路径 exports、对应声明、现有 README 与消费者用法。
  2. 变更 Qy-owned props、emits、slots、expose、defaults 或 tokens 时，补充最小行为/类型证据并保持兼容性口径。
  3. 仅当真实行为差异或复杂边界需要时，建立内部 adapter seam；renderer 决策以 当前 Element Plus implementation ADR 为准。

本契约不决定包版本、构建格式或 npm 解析；这些见 包 exports 与宿主 runtime。

QyPopconfirm ​

QyPopconfirm 的稳定面是 Qy-owned 的确认语义：title、受控/非受控 open、confirmLoading、closeOnConfirm、variant、confirmType、placement 与 width。插槽仅承诺 reference、title 和 icon；事件为 update:open、open-change、confirm、cancel 与携带 Qy 关闭原因的 close(reason)。业务侧不依赖 Element Plus 实例、原始事件对象、teleport/popper 参数或底层 CSS 变量。

QyDialog ​

QyDialog 的稳定面是受控 open、update:open、open-change、confirm、cancel、close(reason)、opened 和 closed。QyDialogCloseReason 冻结为 confirm | cancel | header | escape | overlay | external。默认 footer 由 showFooter、showConfirm、showCancel、confirmText、cancelText、confirmLoading 和 confirmDisabled 控制；宿主持有异步业务并在成功后关闭，Dialog 不接收任意业务 Promise。

宽度、顶部距离、全屏、最小化、销毁、拖拽、锁滚动和显式关闭策略均使用 Qy-owned props。header、footer、footer-left 和 footer-append 是稳定 slot；唯一公开方法为 handleMinimize()。公共类型不暴露 Element Plus props、实例、原始事件、DOM/VNode/Node/Store 或 --el-*。

旧 modelValue、字符串 layout、confirmProps、ok 和任意 Element attrs 由独立 @qynpm/qy-dialog-legacy 薄 adapter 过渡承接，不进入 QyDialog 当前契约，也不作为新业务 API。

QyWatermark ​

QyWatermark 的稳定面是容器内平铺水印：content、image、zIndex、rotate、width、height、gap、offset 和 Qy-owned font；只承诺 default 插槽。图片优先，加载失败回退到文字；覆盖层不接收指针事件，容器变化和当前 renderer 可观察到的节点篡改由内部实现恢复。业务侧只依赖安全容器属性 class、style、id、title、role、data-*、aria-*，不依赖 Element Plus props、实例、DOM、事件、expose 或 CSS 变量。

QyIframe ​

QyIframe 的稳定面是带必填 src 与无障碍 title 的原生嵌入页面；二者去除首尾空白后任一为空时不渲染 iframe。src 变化时更新地址，reloadKey?: string | number 变化时重建 iframe，使相同地址也可受控 reload。组件支持 loading、sandbox、allow、referrerPolicy、allowFullscreen，load 与 error 仅为无参数通知，不暴露 DOM Event。组件填满宿主提供的容器，不感知应用头部高度，不覆盖全局 resize 监听，不模拟加载时长，也不接管会话、地址白名单或跨域通信。业务侧只依赖安全根属性，不依赖 DOM ref、Element Plus 或宿主运行时对象。
